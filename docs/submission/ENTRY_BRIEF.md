# VOLTRO 출품 기획 원고

2026-11-13 KST 작성. 공식 접수양식에 옮길 수 있는 서비스·기술 원고다. 팀명·참가자·연락처·서명은 참가자가 실제 정보로 작성한다. 아래 사업 지표는 실적이 아니라 검증 계획과 목표다.

## 한 줄 소개

VOLTRO는 전기차의 배터리 잔량과 전비를 바탕으로 경로별 소비 에너지와 도착 잔량을 비교하고, 분기점에서 추가 시간과 절약 가능한 에너지를 함께 설명하는 Pleos용 주행 의사결정 보조 앱이다.

## 해결할 문제와 고객

첫 고객 가설은 주말 장거리 이동을 계획하는 전기차 운전자다. 남은 배터리로 목적지에 도착할 수 있는지, 조금 더 시간이 걸리는 경로를 선택할 가치가 있는지 판단할 때 거리·시간·SOC를 각각 확인하는 부담을 줄인다. 장거리 일정이 잦은 소규모 전기차 업무 차량 운영자를 후속 실증 대상으로 삼는다.

운전자가 묻는 질문을 하나의 화면으로 연결한다. “어떤 경로가 얼마나 덜 쓰는가?”, “몇 분이 더 걸리는가?”, “도착했을 때 내가 정한 잔량을 확보하는가?”가 핵심이다. 검색·조건 설정은 출발 전에 하고, 재생 중에는 분기점에서 유지/변경 두 가지 선택을 제공한다. 실제 차량 주행 상태에 따른 UX 제한은 후속 실차 검증 범위다.

## 핵심 경험과 차별화 가설

1. **차량 맥락의 비교:** Pleos Vehicle SDK의 SOC 읽기와 지원되는 누적 전비를 경로 거리 기반 계산에 연결한다. 배터리 용량과 SDK가 제공하지 않는 전비는 설정값으로 표시한다.
2. **설명 가능한 선택:** 최소 도착 SOC·허용 추가 시간·최소 절약량으로 추천한다. 추천 근거, 잔량 여유, 전비가 20% 낮아지는 비교 가정을 함께 제시한다. 이 가정은 예측 정확도나 확률 범위가 아니다.
3. **막힌 상황의 다음 행동:** 모든 경로가 잔량 조건에 미달하면 시작을 막고 최소 출발 SOC와 추가 배터리 에너지를 표시한다. 완충으로도 부족하면 중간 충전 계획이 필요하다고 안내한다. 충전소 경유 최적화는 구현하지 않았다.
4. **분기점의 같은 기준 비교:** 공통 구간 이후의 추가 시간과 에너지를 비교하고, 운전자 승인 후에만 재생 경로를 바꾼다. 변경 실패 시 기존 경로를 유지한다.
5. **검증 가능한 시연:** 성공·잔량 부족·전환 실패 시나리오, 프로세스 종료 후 일시정지 복구, 완료 리포트와 기기 이력으로 판단 전후를 확인할 수 있다.

## 대표 시연과 성과의 해석

강릉역 오프라인 데모는 같은 차량 입력(출발 SOC 68%, 전비 5.2 km/kWh, 사용 가능 용량 70 kWh)을 사용한다. 빠른 경로는 180 km / 130분 / 약 34.6 kWh, 절전 경로는 165 km / 145분 / 약 31.7 kWh다. 분기점에서 승인하면 계산상 약 2.9 kWh를 덜 쓰고 가상 시간은 15분 늘어난다.

이는 고정된 합성 시나리오에서 계산한 차이다. 실제 도로에서 측정한 절약률·예측 정확도·고객 성과로 주장하지 않는다. 실제 도로 모드에서는 OSM 지도와 OSRM 응답의 후보 1~3개를 사용하며 결과 수치가 달라진다. 도로 재생 중 위치와 에너지도 추정값이다.

## 기술 구현

- Kotlin Android 앱: ViewModel·StateFlow·Coroutines, Repository 경계, SQLite 완료 이력, AtomicFile 재생 체크포인트.
- 공식 Vehicle 2.3.2 SDK: SOC capability 확인과 읽기 snapshot. 미지원·timeout은 오류로 표시하며 기존 입력값을 보존한다.
- OSM·OSRM: 실제 지도와 도로 geometry·거리·시간 검증, viewport 지도 요청, HTTP 캐시, 공급자 출처 표시와 요청 간격 제한.
- FastAPI: 에너지 계산·합성 경로·분기점 평가·멱등 완료 저장을 검증하는 개발 서버. release는 로컬 HTTP 개발 서버 기능을 비활성화한다.
- 재생 복구: 5초 간격 및 중요한 결정·일시정지 시 기기 내 기록. 24시간 유효하며 사용자의 복구 선택 후 정지 상태로 표시한다. 완료·취소 후 삭제한다. 완료 기록이 남아 있으면 재생보다 완료 리포트를 우선한다.

## 사업성 검증 계획

아래 수치는 실제 사용자 수나 매출 예측이 아닌, 첫 파일럿의 의사결정 기준이다.

| 단계 | 실행 | 판단 기준(목표) |
|---|---|---|
| 문제 검증 | 장거리 이용 운전자 10명 인터뷰 | 6명 이상이 최근 잔량·시간 선택의 어려움을 실제 사례로 설명 |
| 사용성 검증 | 운전자 10명이 정차 상태에서 비교·전환 과제 수행 | 8명 이상이 추천 이유와 도착 잔량을 도움 없이 설명 |
| 4주 파일럿 | 동의한 운전자 30명 모집, 주행 전후 기록 검토 | 21명 이상 첫 경로 분석, 4주차 11명 이상 재사용 |
| 실측 검증 | 동의된 차량 데이터로 경로별 예측/실측을 짝지어 수집 | 비교 가능한 50회 이상 확보 후 오차·순위 역전·실패 비율 공개 |

초기 예상 MAU 계획값은 파일럿 모집 규모인 30명으로 둔다. 실제 MAU·재방문율·구독 전환율은 아직 측정하지 않았다. 추정 트래픽이나 절약 금액을 현재 성과로 쓰지 않는다. 후속 사업 모델 가설은 차량용 무료 경로 비교 경험과 소규모 업무 차량의 에너지 리포트 유료 실증이다. 가격·유료 전환·운영 지도 공급 비용을 검증하기 전 매출을 추산하지 않는다.

## 확장과 실차 검증 순서

1. 현재 시연 범위로 정차 상태 사용성 검증과 안정적인 제출 시연을 완료한다.
2. 국내 통행 제한·교통 데이터와 운영 공급자 계약을 확보하고, 지원되는 공식 내비 연동의 요청·결과 이벤트를 검증한다.
3. 실제 차량의 읽기 권한·입력 최신성·위치 정확도·주행 UI 정책을 검증한다. TTS는 제공 SDK·오디오 정책 확인 후 별도 진행한다.
4. 차량별 실측 소비량으로 예측 오차와 추천 순위를 평가한 뒤 보정 모델을 도입한다. 충분한 근거 이전에 AI 예측·실차 절약 성능을 주장하지 않는다.

## 개인정보와 현재 제약

로그인·광고·분석 SDK는 추가하지 않았다. 완료 이력은 최근 50개를 기기에 저장하며 정밀 좌표 이력은 포함하지 않는다. 재생 복구 파일은 경로 geometry·진행 위치·당시 차량 입력을 일시적으로 저장하며 OS 백업 대상에서 제외한다. 지도 요청에는 viewport 타일, 도로 요청에는 현재 고정 출발지와 선택 목적지 좌표가 공개 공급자로 전송된다. 운영 서버 인증·개인정보 정책·실차 UX 인증·Pleos Market 심사는 완료하지 않았다.
